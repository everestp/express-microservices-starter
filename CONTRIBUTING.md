# Contributing

1. Open an issue for significant behavior or architecture changes.
2. Keep changes scoped to the owning service and use shared contracts for boundary types.
3. Add or update tests and documentation for changed behavior.
4. Run `pnpm lint`, `pnpm typecheck`, and the relevant test command when dependencies are available.
5. Use Conventional Commits and include a Changesets entry for publishable package changes.

Do not commit `.env` files, signing keys, credentials, or production data. See `SECURITY.md` for vulnerability reporting.
